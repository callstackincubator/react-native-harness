# Architecture decision records

Internal ADRs for React Native Harness. One file per decision, named
`NNNN-short-title.md` with a zero-padded sequence number that is never reused.

Each ADR keeps to these sections, in this order, and stays concise: `Status`
(Proposed, Accepted, Superseded by ADR-NNNN, Deprecated), `Date`, `Context`
(the problem), `Decision` (what we build), `Architecture impact`,
`Compatibility and conflicts`, `Expected outcome` (merge gates), `Not
building`. Add `Verified facts` when the decision rests on measurements or
third-party behaviour that was checked, with the version checked.

Do not edit an accepted ADR to change the decision; write a new one that
supersedes it.
