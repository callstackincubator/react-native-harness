Large test files no longer fail with `app heartbeat timed out` while the app evaluates them. Harness now checks the app connection with WebSocket pings, which the app answers natively even while its JS thread is busy, and limits how long the JS thread may be blocked by the timeouts you already configure: a test's `testTimeout` plus 5 seconds, `bundleStartTimeout` while a test file loads, and 20 seconds otherwise. When the JS thread stays blocked longer, the error names the test or file, and `testTimeout` now also applies to tests that block the JS thread synchronously. The CLI and the app runtime must use the same Harness version.
